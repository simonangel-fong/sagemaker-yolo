## Layout

```
k6/
├── docker-compose.yml    two services: prepare (corpus) + k6 (any scenario)
├── data/                 generated corpus (gitignored)
├── reports/              generated run reports (gitignored)
└── script/
    ├── prepare-images.js Node pre-step: data/raw -> ../data/corpus.json
    ├── smoke.js          steady RATE req/s -- contract check
    ├── load.js           stepped ramp 1..MAX req/s -- find the knee
    └── lib/
        ├── config.js     env-var configuration shared by every scenario
        ├── images.js     SharedArray loader over the corpus
        ├── ready.js      readiness probe used by every setup()
        └── predict.js    one predict request + the response checks
```

## Metrics threshold

`smoke.js` — pass/fail gate:

| Threshold         | default | description                        |
| ----------------- | ------- | ---------------------------------- |
| `http_req_failed` | 0       | no request may fail                |
| `checks`          | 1       | no check may fail                  |
| `plate_detected`  | >=0.8   | most images must yield a detection |

`load.js` — error budget, since the point is to find the breaking point:

| Threshold         | default  | description                        |
| ----------------- | -------- | ---------------------------------- |
| `http_req_failed` | <0.01    | 1% of requests may fail            |
| `checks`          | >0.95    | 5% of checks may fail              |
| `predict_latency` | p(95)<5s | tail latency stays usable          |
| `plate_detected`  | >=0.8    | most images must yield a detection |

### Environment variables

| Variable        | Default                         | Description                                                  |
| --------------- | ------------------------------- | ------------------------------------------------------------ |
| `BASE_URL`      | `https://yolo.arguswatcher.net` | Base url under for test                                      |
| `MODEL`         | `sagemaker-yolo`                | Path segment; the proxy serves its deployed model regardless |
| `CONF`          | `0.25`                          | Per-request confidence filter (the UI slider)                |
| `RATE`          | `1`                             | `smoke` only — requests started per second                   |
| `DURATION`      | `1m`                            | `smoke` only — how long to hold that rate                    |
| `MAX`           | `20`                            | `load` only — peak req/s the ramp climbs to                  |
| `STEPS`         | `5`                             | `load` only — steps between 1 and `MAX`                      |
| `STEP_DURATION` | `30s`                           | `load` only — how long each step is held                     |
| `RAMP`          | `10s`                           | `load` only — transition time between steps                  |
| `CORPUS`        | `/corpus/corpus.json`           | Corpus path (`k6/data/corpus.json` for a local run)          |
| `TIMEOUT`       | `120s`                          | Per-request timeout; a cold endpoint is slow                 |
| `SRC`           | `/input/raw`                    | `prepare` only — source images                               |
| `OUT`           | `/output/corpus.json`           | `prepare` only — corpus destination                          |
| `COUNT`         | `30`                            | `prepare` only — images in the corpus                        |

### Build the corpus

```sh
# prepare images: default 30 images; export in data/raw;
docker compose -f k6/docker-compose.yml run --rm prepare
# source        /input/raw
# images found  556
# skipped       8 over the 4.0 MB base64 cap
# selected      30
# size range    0.0 MB - 3.0 MB
# corpus        /output/corpus.json  (13.6 MB base64)

# prepare 50 images
docker compose -f k6/docker-compose.yml run --rm prepare --count 50
```

## Smoke test

Constant `RATE` req/s for `DURATION`.

```sh
# smoke test (smoke.js is the default scenario)
docker compose -f k6/docker-compose.yml run --rm k6

# 5 request/second for 30 seconds
RATE=5 DURATION=30s docker compose -f k6/docker-compose.yml run --rm k6
```

---

## Load test

Steps 1 -> `MAX` req/s, holding `STEP_DURATION` at each level.

```sh
# 4 -> 8 -> 12 -> 16 -> 20 req/s, 30s at each
docker compose -f k6/docker-compose.yml run --rm k6 load.js

# push harder, in more steps
MAX=40 STEPS=8 docker compose -f k6/docker-compose.yml run --rm k6 load.js
```

Asking for 20 req/s delivered 10.8 — the endpoint is serverless with
`MaxConcurrency=5`, so past ~11 req/s requests queue rather than go faster.
Raise `MaxConcurrency` to move the ceiling.
