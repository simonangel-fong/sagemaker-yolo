Business Challenge

Computer vision models like YOLO are popular for object detection in manufacturing.

Integrating these computer vision models reliably into business applications remains a significant challenge.

This project demonstrates an end-to-end MLOps workflow by training, deploying, and serving a YOLO model that detects vehicle license plates.

Machine Learning

The YOLO model is trained with Amazon SageMaker Studio, following a repeatable MLOps lifecycle:

  • Data collection — collect images of license plates.
  • Feature engineering — label images.
  • Model training and experiment tracking — run training code with a SageMaker pipeline and log metrics to MLflow.
  • Evaluate model — register the model only when mAP50-95 clears the 0.70 gate.
  • Package and deploy — serve the model from a SageMaker serverless endpoint.
  • Integrate the inference endpoint with the web application.

CPU vs GPU

The same YOLO model, trained on the same dataset with the same hyperparameters, on two instance types.

Instance Specification GPU Rate per hour ($) Total min Total cost ($)
ml.m5.xlarge(cpu) 4vCPU, 16 GiB N/A 0.257 27.8 0.379
ml.g4dn.xlarge(gpu) 4vCPU, 16 GiB Yes 0.818 2.2 0.029

The GPU instance costs ~3x per hour but finishes ~11x faster, so the run is roughly ~12x cheaper overall.

Inference Deployment

  • Promote the model — approve a version in the sagemaker-yolo model package group.
  • Serve the approved model from a SageMaker serverless endpoint, so idle time costs nothing.
  • Integrate the endpoint with the web application through the Lambda proxy behind CloudFront.
  • Monitor application performance metrics with Cloudwatch Dashboard and costs with AWS Budgets.
